# PARALLAX — Software Engineering Website

A Next.js 15 + React + TypeScript website for PARALLAX, using the Twilight Bloom brand palette. The contact enquiry API stores submissions in Neon PostgreSQL.

## Included

- Responsive multi-page marketing website
- Services, solutions, work and project detail pages
- Contact form with Zod validation
- Server-side Neon PostgreSQL insertion using `@neondatabase/serverless` (HTTP driver suited to Vercel route handlers)
- Idempotent contact submissions using a unique submission UUID
- Cloudflare Turnstile verification
- Upstash Redis rate limiting
- Neon SQL migrations for enquiries, internal notes and activity history
- Private admin area (`/admin`) with sign-in, enquiry list, status pipeline, notes and activity timeline
- Optional email alert to the owner for each new enquiry (Resend)
- SEO metadata, sitemap and robots.txt

## Requirements

- Node.js 20.9+
- pnpm 9+ (or npm)
- Neon project and PostgreSQL branch
- Cloudflare Turnstile widget
- Upstash Redis database for production rate limiting
- Vercel account for deployment

## 1. Install

```bash
pnpm install
```

The Neon CLI setup (`neon init` and `neon deploy`) creates/updates `.env.local` with `DATABASE_URL` and related Neon variables. Do not overwrite that file with `.env.example`. If you need a fresh local environment, copy `.env.example` to `.env.local` first, then run `neon deploy` again.

## 2. Create the contact table

Run `neon/migrations/0001_contact_enquiries.sql` against the `production` branch database using the Neon SQL Editor, or with a PostgreSQL client connected to the `DATABASE_URL` from `.env.local`. This migration is safe to run more than once.

The application uses the server-only `DATABASE_URL`. Never prefix it with `NEXT_PUBLIC_`, expose it to browser code, or commit `.env.local`. The pooled URL generated by Neon is used for the app's short-lived Vercel requests.

## 3. Configure Cloudflare Turnstile

1. Create a Turnstile widget at https://dash.cloudflare.com/.
2. Add `localhost` and your production hostname.
3. Set `NEXT_PUBLIC_TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY`.
4. Set `TURNSTILE_EXPECTED_HOSTNAME` to the hostname serving the form.

The API verifies the token server-side and requires the `contact` action.

## 4. Configure Upstash rate limiting

1. Create a Redis database at https://console.upstash.com/.
2. Set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`.

The contact endpoint fails closed if rate limiting is not configured.

## 5. Run and verify

```bash
pnpm typecheck
pnpm lint
pnpm build
pnpm dev
```

Open http://localhost:3000. Submit the contact form with valid Turnstile verification and confirm the row appears in `public.contact_enquiries` in Neon. Do not test successful submissions without configuring the Turnstile and Upstash credentials.

## 6. Deploy to Vercel

1. Push the repository to GitHub and import it in https://vercel.com/new.
2. Add `DATABASE_URL`, `NEXT_PUBLIC_SITE_URL`, both Turnstile variables and both Upstash variables to Vercel Preview/Production environments. Add `TURNSTILE_EXPECTED_HOSTNAME` too.
3. Run the Neon migration against the production branch.
4. Add your production hostname to the Turnstile widget.
5. Deploy and test a real enquiry.

## API

`POST /api/contact` accepts `submissionId`, `name`, `email`, optional `company`, `projectType`, optional `budget` and `timeline`, `message`, `consent`, and `turnstileToken`. It validates the payload, checks origin when configured, verifies Turnstile, rate-limits by IP, and inserts into Neon. Customer data is never returned through a public read API.

## Private admin dashboard

A single-administrator dashboard is available at `/admin`. It uses a signed, HTTP-only, SameSite=Strict session cookie; the password is stored as a scrypt hash in server-only environment variables. Admin APIs verify the signed session on every request. No admin credential or Neon connection string is sent to the browser.

### 1. Apply the admin migration

Run `neon/migrations/0002_admin_dashboard.sql` in the Neon SQL Editor against the same production branch/database used by `contact_enquiries`. This adds private enquiry notes and activity tables. Status changes are recorded in `enquiry_activity`; the notes table is ready for a future notes interface. Keep the existing `0001_contact_enquiries.sql` data intact.

### 2. Configure one administrator

Add these variables to `.env.local` (and later to Vercel Production environment variables):

```env
ADMIN_EMAIL=you@example.com
ADMIN_PASSWORD_HASH=scrypt$...generated-below...
ADMIN_SESSION_SECRET=...at-least-32-random-characters...
```

Generate the password hash on your own machine. In zsh, from the project root:

```bash
read -s "ADMIN_PASSWORD?Choose an admin password (at least 14 characters): "
echo
ADMIN_PASSWORD="$ADMIN_PASSWORD" node scripts/hash-admin-password.mjs
unset ADMIN_PASSWORD
```

Copy the printed `scrypt$...` hash into `ADMIN_PASSWORD_HASH`. Do not put the plain password in `.env.local`, source code, Git, or chat. Generate a session secret with:

```bash
openssl rand -hex 32
```

Put that output in `ADMIN_SESSION_SECRET`. Ensure `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` are configured: admin login fails closed without the shared rate limiter.

### 3. Run and sign in

```bash
pnpm dev
```

Visit `http://localhost:3000/admin/login`. The dashboard is at `/admin` after signing in. It supports overview counts, searching/filtering enquiries, viewing full enquiry details, updating lead status, and emailing a customer through the device's configured mail app. Status changes are recorded in `enquiry_activity`.

### Security and deployment notes

- Set a strong unique admin password (14+ characters) and keep the session secret private.
- Add `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET`, `DATABASE_URL`, `UPSTASH_REDIS_REST_URL`, and `UPSTASH_REDIS_REST_TOKEN` to Vercel's server-side Production environment variables. Do not prefix secrets with `NEXT_PUBLIC_`.
- Set `NEXT_PUBLIC_SITE_URL` to the real HTTPS production origin.
- The dashboard is a single-admin implementation. It does not yet support employee accounts, password reset, MFA, or in-dashboard email delivery. The Reply action opens the administrator's mail client.
- Keep `.env.local` out of Git. Rotate credentials immediately if they are exposed.


## Admin area

The public site never exposes enquiry data. You read it at `/admin`.

1. Run both migrations in order against your Neon database: `neon/migrations/0001_contact_enquiries.sql` and `neon/migrations/0002_admin_dashboard.sql` (notes and activity tables).
2. Create your password hash, then paste the printed line into `.env.local`:

   ```bash
   ADMIN_PASSWORD='a-passphrase-of-14-or-more-characters' pnpm admin:hash-password
   ```

   The hash must keep the `scrypt:<salt>:<hash>` form. Hashes containing `$` are mangled by Next.js env loading and will make every sign-in fail.
3. Set `ADMIN_EMAIL` and `ADMIN_SESSION_SECRET` (32+ random characters, for example `openssl rand -hex 32`). Restart `pnpm dev` after editing `.env.local`.
4. Open `/admin/login`. Sign-in is rate limited to 10 attempts per 15 minutes per IP and requires Upstash to be configured.

In the dashboard you can search and filter enquiries, move them through the pipeline (new, reviewing, contacted, qualified, proposal sent, converted, closed), add private notes, review the activity history and reply by email.

### Email alerts (optional)

Set `RESEND_API_KEY`, `CONTACT_NOTIFICATION_EMAIL` and `CONTACT_FROM_EMAIL` (a sender on a domain verified in Resend). When all three are present you receive an email for each new enquiry, with the customer's address as Reply-To. A failed email never blocks the enquiry, which is always saved first.

### Admin API (all require the admin session cookie)

- `GET /api/admin/enquiries?status=&q=`: list and stats
- `GET /api/admin/enquiries/:id`: enquiry, notes and activity
- `PATCH /api/admin/enquiries/:id`: change status
- `POST /api/admin/enquiries/:id/notes`: add a note
- `POST /api/admin/login`, `POST /api/admin/logout`, `GET /api/admin/session`

### Production checklist

- Set `TURNSTILE_EXPECTED_HOSTNAME` and `NEXT_PUBLIC_SITE_URL` to your real domain (they default to localhost) and add the domain to the Turnstile widget.
- Add every variable from `.env.example` to your hosting provider's environment settings.
